# v1 – q103 restart + Lacra state transplant (`dawnwalker_lacra_repair.py`, by heeyblitz)

[← Back to README](../README.md) · Previous: [original q103 fix](original-q103-fix.md) · Next: [v2](v2.md)

> **Status: legacy / experimental.** It worked partially on one save pair
> (SaveVersion 134): Lacra appeared, but the duel was broken. Not tested on game version 1.2.
> For a save where q103 closed after protecting Nish, **use [v2](v2.md) instead.**

This page keeps the research and instructions that **heeyblitz** published in this
repository's original README. "I" in the background sections refers to heeyblitz.

---

## Background

I accidentally locked myself out of Lacra's questline earlier in my playthrough.

I didn't notice straight away. By the time I realised that **"A Friend Like This" / q103** had
become unavailable, my playthrough had already progressed several in-game days. Going back to
the old save would have meant losing a lot of progress.

The goal was therefore:

```text
KNOWN-GOOD SAVE
       │
       │ Lacra-related state
       ▼
CURRENT SAVE
       │
       │ targeted repair
       ▼
CURRENT PROGRESS
       +
Lacra quest restored
```

The goal was **not** to replace the current save with the old save. It was to restore only the
state needed to get Lacra's questline working again, while keeping the current playthrough.

## Starting point: the original q103 fix

The starting point was the existing public [original q103 fix](original-q103-fix.md) (`dawnwalker_lacra_fix.py`)
by **AiKiKun** with **Claude Opus 5**. This repository does not claim the original fix as its own.

The original fix restores the q103 quest graph (`QuestHelperImpl`) and removes the facts that kept q103
closed (`QuestSystemImpl`).

## The second problem

In my case, restoring q103 was not enough. The quest could be triggered again, but when the
Lacra encounter started, Lacra herself was still invisible or missing:

```text
q103 restored → quest starts → encounter starts → Lacra should appear → Lacra is invisible / missing
```

This suggested another layer of state was involved. Restoring the quest state did not
necessarily restore the persistent actor state needed for Lacra to actually appear in the
encounter.

## What was investigated

The investigation compared a known-good save with the current save, instead of simply copying
the old save over the current one. The areas investigated were:

- `QuestHelperImpl`
- `QuestSystemImpl`
- `RebelAISubsystem`
- persistent actor state
- actor/community state
- `AttributeSaveSystem`
- world/persistent state
- Lacra references
- `LacraBoss` references
- encounter/spawn state
- q103 facts
- q103 active graph nodes

The important distinction became:

```text
Quest state  ≠  Lacra persistent actor state
```

The goal was to find the smallest relevant piece of state that could be restored from the
known-good save without replacing unrelated current progress.

## The breakthrough

The first patches I tried did **not** make Lacra appear.

The successful test used:

- the **current save** as the base, and
- an **older known-good save** as the Lacra reference.

The relevant Lacra state was restored into the current save, and the result was significant:

> **Lacra physically appeared in the encounter again.**

However, her behaviour was not normal:

- She appeared physically.
- She initially had an abnormal red aura/halo.
- I could not initially kill her normally.
- Letting Lacra kill the player allowed the game to progress beyond the encounter.

That is why this repair is labelled **BETA / EXPERIMENTAL**. The important breakthrough was
that Lacra was no longer completely missing.

## Mechanism

```text
GOOD.sav (reference) + CURRENT.sav (progress to keep)
   │
   ▼
analyze both
   ├── restore q103 if required (same restart as the original fix)
   └── restore experimental Lacra state (RebelAISubsystem)
   │
   ▼
FIXED.sav
```

The **CURRENT** save stays the base save, and the **GOOD** save is only used as a reference for
the Lacra state. Neither original save is overwritten.

### q103 repair

The q103 repair re-inserts q103's active nodes and removes the q103 facts, as the original fix does. The
script checks for facts showing that the current save may already be past the first stage of
q103. In that case it leaves q103 unchanged instead of blindly resetting the quest.

### Lacra repair

The experimental Lacra repair works inside `RebelAISubsystem`. It searches for a
Lacra-related serialised signature:

```text
LACRA_ANCHOR = 20 43 6f 06 9b 3b 00
```

When the signature is found exactly once in each save, the script replaces a **25-byte field**
in CURRENT with the matching 25-byte field from GOOD, starting at the observed offset:

```text
GOOD
RebelAISubsystem
      │
      └── Lacra signature
              │
              └── 25-byte state
                       │
                       ▼
                 transplant
                       │
                       ▼
CURRENT
RebelAISubsystem
      │
      └── same Lacra state location
```

The script deliberately does **not** copy the whole `RebelAISubsystem`. It also refuses to
guess if the signature is not unique:

```text
GOOD    != exactly 1 match
CURRENT != exactly 1 match
        ↓
       ABORT
```

This is intentional: a failed repair is better than blindly changing an unknown region of a
save.

### Other safety checks

- The script refuses to continue if GOOD and CURRENT have different SaveVersions.
- It warns if the SaveVersion isn't 134.

## Prerequisites

- Windows
- Python 3
- *The Blood of Dawnwalker*
- An Oodle decompressor, either `ooz` or `oo2core_9_win64.dll` (see [setup](setup.md)).
  The examples below use `ooz`.
- **Two saves, both from SaveVersion 134:**
  - a known-good save (GOOD)
  - your current save (CURRENT)

### GOOD vs CURRENT

This distinction is extremely important.

- **GOOD** is an earlier save where Lacra's state is known to be correct. It is used only as a
  **reference**. It is not the save you want to continue playing from.
- **CURRENT** is the save with the progress you want to keep. It is the base of the repaired
  save.

```text
GOOD
ManualSave75.sav
       │
       │ reference only
       ▼
CURRENT
ManualSave79.sav
       │
       │ keep this progress
       ▼
ManualSave_LacraFix.sav
```

Do **not** simply replace your current save with the old GOOD save. That defeats the purpose of
the repair.

## Usage

Download `dawnwalker_lacra_repair.py` and put it somewhere convenient, next to `ooz.exe` (or
pass the full path to `ooz`).

### Basic repair

```bat
python dawnwalker_lacra_repair.py ^
    --good ManualSave75.sav ^
    --current ManualSave79.sav ^
    --output ManualSave_LacraFix.sav ^
    --ooz ooz.exe
```

- `ManualSave75.sav` is the known-good reference save.
- `ManualSave79.sav` is the current save whose progress should be kept.
- `ManualSave_LacraFix.sav` is the new repaired save.

Replace these filenames with your own. To use the DLL instead of `ooz`, replace
`--ooz ooz.exe` with `--oodle-dll oo2core_9_win64.dll`.

### Analyze mode

Before changing anything, you can analyse both saves:

```bat
python dawnwalker_lacra_repair.py ^
    --good ManualSave75.sav ^
    --current ManualSave79.sav ^
    --analyze ^
    --ooz ooz.exe
```

It reports:

- the GOOD and CURRENT SaveVersions
- the `RebelAISubsystem` sizes
- how many times the Lacra signature occurs
- the GOOD and CURRENT Lacra bytes, and whether they differ
- the q103 active state
- which q103 nodes would be restored
- which q103 facts would be removed

### Repair modes

By default the script runs both the q103 repair and the experimental Lacra repair.

**Only the q103 repair** (skip the Lacra patch):

```bat
python dawnwalker_lacra_repair.py ^
    --good GOOD.sav ^
    --current CURRENT.sav ^
    --output FIXED.sav ^
    --no-lacra ^
    --ooz ooz.exe
```

**Only the experimental Lacra repair** (skip the q103 repair). This is useful if the original fix was already
applied and the only remaining problem is that Lacra is missing during the encounter:

```bat
python dawnwalker_lacra_repair.py ^
    --good GOOD.sav ^
    --current CURRENT.sav ^
    --output FIXED.sav ^
    --no-q103 ^
    --ooz ooz.exe
```

## Testing status

The successful test used:

```text
GOOD:        ManualSave75.sav
CURRENT:     ManualSave79.sav
SaveVersion: 134
```

The result:

```text
q103 restored → Lacra encounter triggered → Lacra physically appeared
```

Lacra still behaved abnormally in that test:

```text
Lacra visible
    + red aura/halo
    + could not initially be killed normally
    + letting Lacra kill the player allowed progression
```

> ⚠️ The Lacra-specific repair is **not proven to be a universal fix**. More save pairs need to
> be tested. It has not been tested on game version 1.2.

## Expected results

The most important test is **not** whether the journal says q103 is active. It is this:

> **When the Lacra encounter starts, does Lacra physically appear?**

Possible outcomes:

1. **Lacra appears normally.** Excellent; report the result.
2. **Lacra appears but is invulnerable.** Some encounter or combat state may still need
   investigating.
3. **Lacra appears with a red aura/halo.** This matches the original successful test.
4. **Lacra can be damaged, but the encounter does not progress.** Report the exact behaviour.
5. **Lacra kills the player and the quest progresses.** This also matches the original
   successful test.
6. **Lacra stays invisible.** The experimental state was not enough for that save.
7. **The game crashes.** Stop testing that output save and go back to your backup.

---

## Pros

- Lacra physically appears again, which the original fix alone couldn't achieve.
- It plays the original quest content (investigation, duel, interrogation) instead of
  skipping it.
- It makes a small, targeted edit with strict uniqueness checks, and never guesses offsets.
- It has an `--analyze` mode for inspecting both saves before writing anything.

## Cons

- **The duel is broken.** Lacra has a red aura and can't be killed normally. The quest only
  moved on after she killed the player.
- **It needs an older GOOD save** in which Lacra still works, with the same SaveVersion as
  CURRENT.
- It was validated on a single save pair, on SaveVersion 134 only. **Not tested on game 1.2.**
- Nobody knows what the 25-byte field means. It was found by comparing saves, not by reading
  the game logic.

## Why it couldn't be fully fixed

[v2's research](v2.md#why-the-restart-approach-could-never-work) later explained this
behaviour:

- `q103_main` spawns LacraBoss only once, as its first step. The game runs that step
  automatically at the end of the Prologue.
- The game drops restored spawn actions when it loads a save.
- So the transplant got Lacra back into the world, but not as a boss that the quest had
  properly spawned.

That is why v2 dropped the restart approach altogether.

## Troubleshooting

### "Lacra signature was not unique"

The script intentionally refuses to guess. Run `--analyze`. If the signature count is not
exactly `GOOD=1` and `CURRENT=1`, do not force the patch manually. Report the result instead.

### GOOD and CURRENT have different SaveVersion values

The repair expects matching save versions and won't continue if they differ. Use saves from
compatible game/save versions.

### The game loads the wrong save

Check:

- Steam Cloud (see [setup](setup.md))
- the filename and timestamp
- the save thumbnail and metadata
- the in-game day

Don't rely only on the number in the filename.

### q103 had already progressed

The script leaves q103 unchanged when facts show the quest is already past its first stage.
This is another reason to run `--analyze` first.

## If it doesn't work

Don't keep overwriting your saves. Keep `GOOD.sav` and `CURRENT.sav` unchanged.

To report a failed test, provide:

1. Game version
2. Platform
3. SaveVersion
4. GOOD save filename
5. CURRENT save filename
6. Whether the original q103 fix was already applied
7. Whether q103 triggered
8. Whether Lacra appeared
9. Whether Lacra could be damaged
10. Whether the encounter progressed after the player died
11. Any crash or error message

If possible, provide the GOOD and CURRENT saves so their structures can be compared. For
successful results, use the template in the [README](../README.md#reporting-results).
