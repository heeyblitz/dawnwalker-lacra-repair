# v2 – Continue into Song of the Mountain (`dawnwalker_lacra_fix_v2.py`, by Wllader)

[← Back to README](../README.md) · Previous: [v1](v1.md) · Before that: [original q103 fix](original-q103-fix.md)

> **Status: recommended.** Confirmed in game on one save (SaveVersion 134, played on 136).
>
> ⚠️ **Not tested on game version 1.2 (released November 11, 2026).**

`dawnwalker_lacra_fix_v2.py` continues Lacra's questline into **Song of the Mountain** on a
save where **A Friend Like This** (quest `q103`) has already closed. That happens when you
protect Nish from Lacra or refuse to cooperate with her.

The script never touches your original save. It writes a **new** `ManualSaveN` slot, with a
`.meta` and `.png` copied from the source.

## Mechanism

The [original q103 fix](original-q103-fix.md) and [v1](v1.md) tried to restart q103 in the middle,
which [can't work](#why-the-restart-approach-could-never-work). v2 doesn't replay the duel at
all. Instead it **skips ahead**:

1. It writes the facts the investigation would have set if you had cooperated with Lacra.
2. It puts q103 at the very start of **Song of the Mountain** (`q103_path`), in its
   *"Lacra waits for you"* variant. Only *wait* nodes are used, because waits are the only
   nodes the game resumes from a save.
3. At nightfall the night wait fires, and the game spawns Lacra at her meeting point
   **itself**. From the conversation onwards the quest runs normally.

### What the script changes

| Save section | Change |
|---|---|
| `QuestSystemImpl` (facts) | Clears every q103 investigation/interrogation fact. Then sets the "investigation finished, Lacra cooperates and waits" state: `lacra_cooperation`, `interrogation_done`, `proceed`, `lacra_met`, `lacra_duel_victory`, `got_info`, `Lacra_wait = 2`, alley/roof progress, and so on. `ProtectedNishFromLacra` and `lacra_no_cooperation` end up removed. |
| `QuestHelperImpl` (quest graph state) | Adds the instance path `0 → 18878 → 16820` (q103 → `q103_path`) to the path table. Marks q103 and its `q103_path` sub-quest as running, with the active waits of the *"Lacra waits for you"* start variant. |

Nothing else in the save is modified. The map container node grows only because it holds the
two edited records. Unlike v1, v2 does **not** touch `RebelAISubsystem`.

## Prerequisites

- Python 3.8+. No packages need installing.
- An Oodle decompressor: `ooz` or `oo2core_9_win64.dll` (see [setup](setup.md)).
- **One save**, made **after** A Friend Like This closed. Ideally q103 closed with
  *"protected Nish / no cooperation"*.
- The save must not have been edited by the [original q103 fix](original-q103-fix.md) or
  [v1](v1.md). Those reopen q103, and v2 refuses to run while q103
  is active.
- The save must not already be past the quest (village reached, `path_proceed`, and similar).
- Tested SaveVersions: 134 and 136. Any other version prints a warning, but the script still
  runs.

## Usage

1. **Back up** your whole save folder (see [setup](setup.md)).
2. Run the script:
   ```
   python dawnwalker_lacra_fix_v2.py "C:\Users\<you>\AppData\Local\Dawnwalker\Saved\SaveGames\ManualSave1.sav" --ooz ooz.exe
   ```
   Use `--oodle-dll oo2core_9_win64.dll` instead of `--ooz` if you have the DLL. Use
   `--out-name` to pick the slot name; the default is the first free `ManualSaveN`.
3. Start the game, load the new slot and **wait until night**.
4. Find Lacra at her meeting point. In the tested save she waited in the **cave next to
   Stonefall**; walkthroughs place the meeting near **Crown Rock**.
5. Talk to her. The scene *"Lacra by the mountain"* plays, and Song of the Mountain continues
   normally from there.

## Pros

- **Works with the game's own logic.** The game spawns Lacra itself, so she is a normal,
  working character, unlike v1's red-aura Lacra.
- **Only needs the save you want to continue.** No older GOOD save required.
- Leads straight into Song of the Mountain, confirmed in game.
- Minimal edit: only quest facts and quest-graph state; no actor or AI data.
- Safety checks: refuses to run if q103 is still active or the save is already past the quest.
- The "too late" timer is not started, so Lacra will not leave after a few in-game days.

## Cons

- **Not tested on game version 1.2** (November 11, 2026). Quest node ids or the save layout
  could have changed, so treat 1.2 saves as completely untested.
- **Tested on one save only:** a Steam save, SaveVersion 134, patched and then played on build
  **CL-265636** (SaveVersion 136).
- **Only the cooperation outcome is set up.** If your q103 ended differently (for example
  Lacra killed, or Lacra drained), the script still writes the cooperation state, but that
  case is untested.
- **The duel with Lacra and the Nish interrogation are skipped**, and you get no XP for them.
  Nothing from them is needed later: Nish gives no item, and the facts about Nish are not read
  by Song of the Mountain or the village part.
- **No journal entry or map marker until you talk to Lacra.** The objectives are normally
  added in the skipped scene, so they appear only once the mountain scene plays.
- **A Friend Like This stays "done" in the journal.** The journal and the quest logic are
  stored separately, and the script only edits the quest logic.

## Methodology: how the fix was found

### Starting point

The [original q103 fix](original-q103-fix.md) and [v1](v1.md) both tried to **restart q103 in the
middle**. They re-inserted the quest's "active node" entries and deleted the q103 facts. The
result:

- The quest ran again. The alley clues and the house scenes worked.
- The cinematic with Lacra played, but **the boss never spawned**, or with v1's state
  transplant she appeared in a broken state. Either way, the duel could not be finished
  properly.

Most of the work below explains why, and finds a way around it. All of it was done on build
CL-265636, before the 1.2 update.

### Tools and what each one contributed

| Tool | Used for | What it told us |
|---|---|---|
| **[ooz](https://github.com/powzix/ooz)** (Oodle Kraken decompressor) | Unpacking the `DSAV` save container, which is made of `CHNK` blocks compressed with Kraken | Made the raw save data readable. Writing back needs no Oodle: the game accepts "stored" Kraken blocks. |
| **`dawnwalker_lacra_fix.py`** (original q103 fix) | Save parsing helpers: node tree, name table, node replacement, fact-name hash (UE `Strihash_DEPRECATED`) | The base layer every later tool and v2 build on. |
| **Python diff scripts** (ad hoc) | Comparing saves before and after each in-game action: facts, active quest nodes, AI actor records, data-layer states, object states | Showed which records the game itself changes when you investigate a clue, enter the house or meet Lacra. Most findings below come from these diffs. |
| **[DwSav](https://www.nexusmods.com/thebloodofdawnwalker/mods/285)** (save viewer) | Its asset cache, `FactTags.ini` and `quests.json` (the viewer itself fails on build CL-265636) | `FactTags.ini` turned fact hashes back into names such as `q.m.103.fact.lacra_no_cooperation`. `quests.json` showed that Song of the Mountain is a journal entry of the **same quest q103**, not a separate quest. |
| **Web search / Nexus** | Finding the AES key and the modding tools | The game's `.pak`/`.utoc` files are AES-encrypted. The key is community-shared on the Nexus mod page ["Make your own Mapping File"](https://www.nexusmods.com/thebloodofdawnwalker/mods/136) (credited to *persiangirl*). We checked it against the current build by decrypting the container's directory index, which reads as the expected `../../../` mount point. |
| **[UE4SS for Dawnwalker](https://www.nexusmods.com/thebloodofdawnwalker/mods/18)** + the mapping-file mod | Generating a `.usmap` mapping file for the exact game build (F1 in the main menu) | Without a matching mapping, the quest assets can't be read correctly; DwSav's bundled mappings fail on this build. |
| **[FModel](https://fmodel.app)** | Exporting `/Game/_Dawnwalker/Quest/q103_lacra/` and `Dawnwalker_main_s` as JSON (UE 5.5, the `.usmap` above, the AES key) | **The actual quest logic.** Every quest "sketch" is a graph of nodes (waits, spawns, dialogues, fact setters, sub-quests) with numeric node ids that match the ids in the save. |
| **Graph dump scripts** (`graph.py`, `walk.py`) | Turning FModel's JSON into readable node lists, and walking them forwards and backwards | Answered "what does this active node wait for" and "what has to run before X", including the q103 → Song of the Mountain flow. |
| **[xxhash](https://pypi.org/project/xxhash/)** (Python package) | Testing hash candidates for the save's quest-instance ids | Identified the id scheme as **XXH3-64** (see below). Only needed during research; v2 has the one id it needs hard-coded. |

### What the save looks like (q103 parts)

- **`QuestSystemImpl`** holds the facts: a list of `(u32 hash of the fact name, i32 value)`.
- **`QuestHelperImpl`** holds the running quest graphs in two parts:
  1. A **path table** of quest-graph instances. Each record is a root index, then the chain of
     sub-quest node ids leading to that instance, then `-1`. Example: `0, 18878, 29332, 28945, -1`.
  2. A list of **active nodes** as `(instance id, node id, value)`. Free slots are
     `(0, -1, 0)`.
- **The instance id is XXH3-64 (seed 0) of the path record, with each number packed as a
  little-endian u64:**
  ```
  id = xxh3_64(pack('<Q', 0) + pack('<Q', 18878) + pack('<Q', 16820))  # = 0x67168e74b9544923 (q103_path)
  ```
  FNV, xxHash64, CityHash and various hash-combine schemes were tried first and failed. XXH3
  (Unreal Engine 5's `FXxHash64`) matched all seven known pairs at once:

  | Path | Instance id | Graph |
  |---|---|---|
  | `0` | `0xc77b3abb6f87acd9` | `Dawnwalker_main_s` (root) |
  | `0,18878` | `0x91fbd38d3a5818b7` | `q103_main` |
  | `0,18878,15178` | `0xa00b3ec90b1379fd` | q103 rumours |
  | `0,18878,29332` | `0x17d5904522f26c65` | `q103_investigation` |
  | `0,18878,29332,23545` | `0x7d05516b850846c1` | alley / house |
  | `0,18878,29332,28945` | `0x4b2fc768e7e5317b` | duel / interrogation |
  | `0,18878,29332,28945,26667` | `0xa838bcc66d70f539` | the duel itself |

- **`GameTimeSystemImpl`** holds the game clock as a u64 in milliseconds of game time, at offset 4.
- **The data-layer list** is a record of `(name length, "DataLayer_<GUID>", state 0/1/2)` entries.

### How the engine treats restored quest nodes

These rules came from building test saves and comparing them with the saves the game wrote
after loading them:

| Node kind put into the active list | What the game does on load |
|---|---|
| **Wait on a fact, place, interaction or time of day** | Resumed. If its condition is already true, it fires immediately and the flow after it runs *live*. |
| **Wait on a game timer** ("1 day passes") | Kept, but never fires. A timer only counts in the session where it started. |
| **Action** (spawn, animation, dialogue, …) | Silently dropped; it never runs. |
| **Sub-quest node without saved inner state** | Kept, but idle; its inner graph never starts. |

The practical rule: **you can only start things from a save edit by placing a wait whose
condition is true, so the game runs the following actions itself.**

### Why the restart approach could never work

`q103_main` begins with:

```
Start → spawn guards → spawn LacraBoss (phase q103_start) → alley trigger, door trigger, investigation, …
```

LacraBoss is created **once**, as one of q103's first steps. Because the root graph starts
q103 right after the Prologue (see below), in practice she is spawned at the **end of the
Prologue**, long before the player hears of the quest, and stays hidden in the house. The duel later
only teleports her in, plays a taunt, and waits for her death or low health; it has no spawn
of its own. A mid-quest restore leaves out the spawn, and the spawn is an action, so it can't
be added back through the save. We tested exactly that, and the game dropped it.

This also explains v1's result: copying Lacra's actor state put her back into the world, but
not as a boss that the quest had properly spawned.

The root graph starts q103 directly after the prologue, with no wait in front, so a clean
"start from scratch" through the save is impossible as well.

### Why the original questline closed

The original save had `ProtectedNishFromLacra = 1` and `lacra_no_cooperation = 1`. At the end
of `q103_investigation`:

```
interrogation_done = 1 → lacra_cooperation == 1 ?
    yes → End → q103_main: autosave "got info" → start q103_path (Song of the Mountain)
    no  → "LacraBanished" → q103_main: NoCooperation → q103 ends
```

So nothing was corrupted: the questline ended by design when Nish was protected.

### Dead ends we ruled out (and what each one taught us)

- **Editing only facts on the closed quest.** Song of the Mountain lives inside q103, so facts
  can't start it while q103 is closed.
- **Marking alley/rooftop clues as investigated.** The "count == 5" check only runs right after
  a clue is used, so writing the count does nothing. (We also learned that clue progress is
  driven by interaction events.)
- **Switching on world objects** near the alley. The game kept them, but they gate nothing.
- **Re-adding the LacraBoss spawn node.** Actions are dropped on load.
- **Skipping the duel through "player health ≤ 5 %".** Player health is not stored in the save,
  and the quest stops abilities from taking you below 6 %.
- **Ending the investigation through the "one day passes" route.** Timers restored from a save
  don't count. Started live they do fire, but the chain after them (removing a Lacra who was
  never spawned, then a Coen comment) hung, and saving dropped it.
- **The debug entry points of q103** (`B_Path` and others). They are not wired in the root
  graph.

### The working approach

1. Look at how `q103_path` starts, in its *"Lacra waits for you"* variant (`Lacra_wait ≥ 1`).
   Everything after its Start is either a wait or something those waits trigger live:
   - `9354`: wait for **night** → `lacra_in_house = 0` → remove Lacra → **spawn Lacra at
     `q103_meeting_point`**
   - `16696`: wait for **talking to Lacra** → … → cinematic `q103_05_lacra_by_the_mountain`
   - `361`, `27106`, `6672`, `8142`, `31673`: the other start-up waits
   - The `185` sub-graph is the "too late" deadline and is deliberately left out. `13723` is a
     background helper that isn't needed.
2. Add the missing path record `0,18878,16820` to the path table. The original run never
   entered `q103_path`, so it wasn't there.
3. Put those waits under the instance id `xxh3(0,18878,16820)`. Mark `q103_main` as having
   started `q103_path` (node `16820`, plus the village-mask wait `18853`) and drop the
   investigation's instances.
4. Set the facts the skipped investigation ending would have set (`lacra_cooperation`,
   `interrogation_done`, `proceed`, `Lacra_wait`, …).

On load, the night wait fires at nightfall. The game spawns Lacra at her meeting point itself,
and the quest continues normally from the conversation onwards. This was confirmed in game.
